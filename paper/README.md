# Manuscript and reproduction code

LaTeX source for the GCM manuscript, together with every script that produces the
numbers, tables and figures it contains.

Nothing in the manuscript is typed by hand. Each analysis script writes LaTeX
macros and `tabular` bodies into `results/`, and the manuscript reads them, so
re-running an analysis updates the paper.

## Layout

| path | contents |
|---|---|
| `gcmrk_paper_peerj.tex` | manuscript wrapper (document class, title block, front matter) |
| `gcmrk_macros.tex` | `\tool`, `\previewfig`, and the `\InputIfFileExists` of every generated result |
| `gcmrk_abstract.tex` | abstract body |
| `gcmrk_body.tex` | Introduction through Appendices |
| `references.bib` | bibliography |
| `experiments/` | analysis scripts (below) |
| `results/` | generated JSON, LaTeX macros and table bodies |
| `figures/` | generated figures |
| `data/` | input data |

## Building

```bash
pdflatex gcmrk_paper_peerj
bibtex   gcmrk_paper_peerj
pdflatex gcmrk_paper_peerj
pdflatex gcmrk_paper_peerj
```

The manuscript compiles before any analysis has been run: each generated value
has a `\providecommand` fallback in `gcmrk_macros.tex`.

## Submission bundle

A submission system compiles whatever files it is given in one flat directory,
which the split sources and the `results/` and `figures/` paths do not survive.
`make_submission.py` resolves the whole chain once:

```bash
python3 paper/make_submission.py
```

It writes `submission/`: a single `manuscript.tex` with every macro value, table
body and bibliography entry inlined, the figures copied out as `figure1.pdf` and
so on in citation order, `references.bib`, the class file, a `MANIFEST.txt`, and
the compiled PDF. The bundle needs only `pdflatex` --- no BibTeX pass, no other
files. The script fails rather than falling back if a generated file is missing,
so the bundle cannot carry a placeholder value.

## Analyses

Run from the repository root so that `gcmrk` is importable:

```bash
PYTHONPATH=. python3 paper/experiments/<script>.py
```

**Comparisons against other methods**

- `benchmark_baselines.py` — the main comparison: a replicated noise sweep
  against agglomerative clustering, k-means, spectral clustering, Leiden,
  Louvain, Markov clustering and WGCNA, plus model selection with the cluster
  count unknown and robustness to unstructured genes. ~2.5 h.
- `saelens_benchmark.py` — recovery of curated modules on real expression
  compendia. Requires `data/saelens2018/data/`, unpacked from Zenodo record
  5532578 (`data.zip`, 1.2 GB). `--list` shows the available datasets. ~5 h for
  six datasets at `--n-top 500`, dominated by the factor objective.
- `empirical_comparison.py` — GSE183947 scored by module coherence, Gene
  Ontology over-representation (via Enrichr, needs network access), association
  with tissue type, and split-half reproducibility. ~5 min at `--n-top 200`.

**Model behaviour**

- `misspecification.py` — recovery on data generated by processes the model does
  not assume. Run once per noise level, tagged; the manuscript uses `_n15`:

  ```bash
  PYTHONPATH=. python3 paper/experiments/misspecification.py --noise 1.0 --tag _n10
  PYTHONPATH=. python3 paper/experiments/misspecification.py --noise 1.5 --tag _n15
  ```

  `--generators a,b` restricts the sweep. ~1 h per noise level.
- `diagnostics.py` — the targeted experiments behind the model-selection and
  rank-selection statements: objective value at the planted partition versus the
  optimizer's, rank recovery by BIC and AIC, automatic versus oracle rank,
  modularity at the planted partition, and the two-stage cluster-count recipe.
  ~20 min.
- `scaling.py` — runtime and recovery against gene count. Run it on an otherwise
  idle machine: concurrent jobs distort the timings enough to change the fitted
  growth exponent. The table reports the constrained objective; the factor
  objective costs considerably more on real data.

**Illustrations and support**

- `run_experiments.py` — single-dataset summary table, the convergence,
  model-selection and Pareto figures, Iris, the GSE183947 module figures.
- `iris_validation.py` — Iris as a check that the optimizer reaches a geometric
  index's optimum.
- `decisive.py` — a lighter replicated benchmark against agglomerative
  clustering and k-means; much cheaper than `benchmark_baselines.py` and used
  for the ablation figure.
- `baselines.py`, `simulators.py` — imported by the drivers, not run directly:
  the competing methods behind one interface (with the protocol that gives each
  its most favourable setting), and the data-generating processes.
- `gen_latex.py` — regenerates LaTeX from saved results without re-running the
  optimizer.

Every driver can regenerate its tables and figures from its saved JSON by
calling its `write_latex()` and figure functions, which is much cheaper than a
re-run.

## Requirements

The `gcmrk` package itself needs only NumPy, SciPy, pandas and Matplotlib. The
analysis scripts additionally use scikit-learn, python-igraph, leidenalg and
markov_clustering, and call R for WGCNA.
